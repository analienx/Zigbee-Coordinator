# T832-DIAG-R0 review closure (R01–R16)

Independent review of candidate `780cb92` returned 16 findings. Each item below
is either repaired with new passing tests/gates, or stands with the exact
blocking evidence. Severity: P0 = essential-path break, P1 = real failure of a
claimed discriminator, P2 = latent over-claim or incomplete acceptance.

## R01 — P0: DEBUG.msg lacks the herdsman length prefix → REPAIRED

The exporter now emits `[len]["T832D2:"+hex]` (length-prefixed string, ≤234 B
MT payload against the ≤240 B budget, all envelope bytes counted). The hosted
`interop` job feeds actual C-emitted bytes through the pinned herdsman 10.9.1
UNPI `Frame.fromBuffer` + `ZpiObject.fromUnpiFrame` + `toString()` chain into
both decoders and the collector, asserting field-identical survival plus
rejection of truncation, wrong lengths, unknown schemas and corrupt records.

## R02 — P0: decoders miss the stock Buffer representation → REPAIRED

Both tools extract the DEBUG `string` Buffer (`herdsman-buffer-v1`, DEBUG-line
scoped) and keep an explicitly versioned `text-fallback-v1`. The interop job
exercises the stock shape end to end; the logging namespaces and file-output
prerequisites are documented in the runbook without deploying them.

## R03 — P0: barrier reaches control lines on unvalidated output → REPAIRED

`deploy/t832_capture_barrier.yaml` gates every destructive step on the
previous step's parsed `response_variable` (returncode + JSON fields +
incident-id match); no `continue_on_error` on the destructive path; bounded
stop-confirm polls and waits. `firmware/t832/test_barrier.py` proves the
structure and walks the chain with mocked services through success and six
failure modes, each halting with the latch preserved.

## R04 — P0: TX-ownership and sync-lifecycle gaps → REPAIRED (scope corrected)

An 8-deep TX-ownership FIFO (queue hook → SOF-validated dequeue → TX-finish
resolution) attributes every frame independently: diagnostics, sync SRSPs and
normal frames resolve only their own flags (harness overtake tests). NPI-side
drops reconcile pending flags and repair the FIFO; MT build refusal retires
nothing and counts `DIAG_LOSS` (routine, never first-fault). Repeated SREQs
record `SYNC_ABANDON`. Correction: the NPI sync queue/watchdog does not exist
in this image (linked-image proof, CI absence gate), so the lifecycle is
MT-side SREQ → SRSP dequeue → SRSP finish; there is no watchdog expiry to
hook and none is claimed.

## R05 — P0: production/export imbalance, first-fault eviction, retire-on-send → REPAIRED

Schema-2 batches up to 4 records/frame (48 records/min drain vs ≈20/min
periodic production, drain proven with periodics enabled). Live system records
bypass the rings; the first fault is re-emitted verbatim with a snapshot flag
independently of ring pressure; ring records retire only on MT accept, and own
loss is counted separately from radio faults.

## R06 — P1: reset-cause writer is dead code → REPAIRED

The `Boot.c` writer is removed (its object is not linked). Capture runs as the
first statement of `main()` with a validity magic checked at MT init; invalid
capture emits `BOOT_CAPTURE_INVALID` instead of a bogus cause. CI proves the
call in disassembly plus map linkage; the harness never seeds the globals.

## R07 — P1: NPI trap is invisible → REPAIRED

The central RX-overflow trap records size/available, then spins (preserved).
The TX-path allocation failure and the RX-path allocation failure record with
class-aware reconciliation. Both are covered by harness tests; the trap site
is proven by exact-match patch evidence.

## R08 — P1: collector cursor loses/dupes lines → REPAIRED

Per-file identity cursors resume at committed complete-line boundaries (no
first-line discard), buffer partial tails durably, and note rotation and
truncation explicitly. Covered by append/partial/rotation/truncation tests.

## R09 — P1: latch/permit races and recovery paths → REPAIRED

An OS-exclusive re-entrant lock serializes all mutating commands; tmp files
are pid+time unique; corrupt state fails closed (missing vs corrupt are
distinct); bundle hashes re-verify before permit consumption; manual-clear
refuses corrupt state without `--force`; automatic code paths never use
manual-clear. Covered by concurrency, corruption, tamper and missing-bundle
tests.

## R10 — P1: AF acceptance/confirms unproven → REPAIRED

An 8-deep accept table keys `(srcEp, transID)` parsed at verified per-variant
offsets; SREQ acceptance comes only from the SRSP AF status byte (rejections
recorded with the status); AREQ requests track as unconfirmed; confirms
resolve or record orphan/duplicate/status anomalies; overflow and transaction
reuse are explicit counted events, not silent leaks. Covered by harness tests
with real-offset frames for all three request variants.

## R11 — P1: tick read races → REPAIRED

The tick is read inside the critical section with a cached period, so no
preempting hook can inject a false wrap; multi-field frame state is snapshotted
under one section. Covered by the harness rollover test.

## R12 — P2: capabilities over-claim → CORRECTED

`TASK_MODES` is renamed to `MT_EVENTS` (event-mask observations, honestly
labeled). True ZStack-task and NPI-task progress timestamps plus heap
free/largest (with an unavailable sentinel) are new capabilities with export
paths for every advertised counter (RX bytes, TX count/classes, oldest pending
age, export loss, last command/startup, first-fault snapshot). Task
ready/blocked states and stack watermarks remain PARTIAL: no task-context-safe
query API is reachable, with the exact reason recorded here and in the matrix.

## R13 — P2: identity, continuity, binding → REPAIRED

Wire identity is the immutable `T832_BUILD_ID` (candidate short SHA, CI-gated
against the built commit) plus the capability bitmap; full image SHA-256
association is a validated host binding (`bind-firmware`, required by the
barrier). Boot association is host-side (BOOT record + export/uptime/record
discontinuities, `boot_index`); the constant wire boot slot is documented, not
presented as a counter. Continuity distinguishes wrap, duplicate, replay, gaps
and true reboots (7-day stream test). The last-stage selection uses
boot+chronology.

## R14 — P2: unbounded collection/capture/retention → REPAIRED

Per-run byte budgets, window row caps with truncation flags, per-phase capture
deadlines (failure preserves the latch and never authorizes), source-time-only
windows with unknown-time accounting, naive-timestamp rejection, incident and
host-events retention protecting active evidence. Covered by budget, deadline,
timezone and rotation tests.

## R15 — P2: stability close is elapsed-time only → REPAIRED

`recovery-result` requires normal traffic AND a bounded ZDO check;
`stability-observation` rows feed a coverage rule (≤180 s gaps, all bridge-up,
traffic+ZDO in both halves, no clock anomaly/restart); mid-window outage,
gaps, restarts and stale traffic fail closed. Covered by six stability tests.

## R16 — P2: barrier is a skeleton around an echo → REPAIRED

The candidate is a patch against the actual production watchdog contract
(same three triggers; only the existing validated R2 helper performs the
reset; the existing bounded ZDO `permit_join` check is the recovery proof;
no new ZDO probing, no notifications, undeployed collector service with status
via systemctl/journalctl). Mocked-service chain tests prove no unauthorized
next action is reachable.
