# R4 B4 v4: source candidate acceptance and safety boundary (2026-10-17)

**Change:** additive **SYS F1**, entirely separate from existing stable **SYS F0 v3**. Stacked draft [PR #104](https://github.com/analienx/Zigbee-Coordinator/pull/104) targets verified [B4 PR #100](https://github.com/analienx/Zigbee-Coordinator/pull/100). No merge, install, flash, HA/Z2M runtime change, network formation, NV/security read/write, or RF action.

## Why F1, not retrofit F0

The old MT F0 v3 request is empty and the reply has no transaction nonce; after a timeout, the pinned ZNP Waitress could match a late F0 to a new request. Previously B4 solved this only by permanently quarantining F0 after ambiguous failure. F1 requires exactly **8 caller-provided nonce bytes** and echoes them at fixed offset 132. An independently random host nonce is generated by Node `crypto.randomBytes` just before a manually approved probe. The host compares the entire echo **after** resolving the existing one-owner waiter; a stale/misrouted reply can never become a valid observation. A nonce does not authenticate the coordinator or prove a reboot, and does not justify unbounded retries: F1 remains quarantined after ambiguous errors.

## New fixed ABI

| Field | Offset / size | Meaning |
| --- | --- | --- |
| `R4D4`, major 4, flags 0, LEN 160 | 0..7 | Strict version/size |
| capabilities | 8..11 | 0x02 nonce echo, plus 0x01 **only** after hardware entropy success |
| validity | 12..15 | 0x3F sync-enabled, 0x2C async-only; all other counter bits invalid |
| radio boot identity | 16..23 | 8 random bytes per boot, LE; **zero** if entropy unavailable |
| uptime_ms | 24..27 | 0; no native monotonic provider qualified yet |
| sample_seq | 28..31 | u32 sequenced inside same `OsalPort` CS |
| counters | 32..131 | Same 25 u32 slots as v3; only six metrics implemented |
| host request nonce | 132..139 | Exactly echoed; never persisted in telemetry |
| reset reason | 140..143 | TI `SysCtrlResetSourceGet`; identifies cause, **not** boot uniqueness |
| source fingerprint | 144..151 | 8 bytes derived from pinned v4 overlay source and TI SHA; **not** a hash or attestation of actual ELF bytes |
| ABI minor | 152..153 | fixed zero |
| entropy status | 154..155 | 1 only when one-shot TRNG succeeded and cached nonzero token; otherwise zero |
| reserved | 156..159 | zero, reject nonzero |

The existing 132-byte `R4D3` frame and empty SYS F0 request are unchanged. The legacy donor v2 slot at index5 is unchanged; v4 index5 denotes true `UART2_EVENT_TX_FINISHED` **event notification count**, not packet/USB/ZCL delivery.

## Real pinned TI startup source and failure handling

- Exact TI SDK: `TexasInstruments/simplelink-lowpower-f2-sdk@3615ad5d3f4f271258d18a2f5ce1785064ff9a58`. Existing NPI startup `NPITask_task` calls `NPITask_inititializeTask()` then posts `npiInitializationMutexHandle`, and finally enters `NPITask_process()`. The v4 experiment adds **one** boot identity attempt in this startup window, never inside the F1 request.
- TI `TRNG_init` has its own idempotent `isInitialized` guard (pinned `source/ti/drivers/trng/TRNGCC26XX.c:366–396`). `TRNG_open(0,...)` may return NULL; `TRNG_getRandomBytes` may fail or time out, and its output must not be trusted on failure. The driver generates 64-bit entropy and uses a semaphore in blocking mode.
- **Critical source-review repair:** pinned `TRNGCC26XX_waitForResult` uses `SemaphoreP_pend(..., timeout)`, while the entropy job may still be queued when the wait ends. V4 now calls `TRNG_cancelOperation` **before** `TRNG_close` on non-success, avoiding destruction of the job semaphore while the ISR still owns the job. Its timeout is converted from 100,000 µs into RTOS ticks via `Clock_tickPeriod`; it is **not** a raw `100` ticks.
- Boot token and reason are kept in static RAM and copied in one short `OsalPort` critical section, with **ready flag set last**. No retry on failure, no entropy read on F1, no NV writes, no claim that reset source is unique.
- Practical limits: one-shot 100 ms bounded wait is a startup-latency candidate, **not** proven acceptable to Zigbee security timing, starvation or true live boot until physical R4-07 loaded measurements. A genuine TI ELF symbol and ELF/XML/HEX/BIN parity gate is mandatory but does not prove the runtime entropy operation successfully executes.

Official TI API: [TRNG return status and driver](https://dev.ti.com/tirex/explore/content/simplelink_cc13xx_cc26xx_sdk_8_32_00_07/docs/drivers/doxygen/html/_t_r_n_g_8h.html); [reset source](https://dev.ti.com/tirex/explore/content/simplelink_cc13xx_cc26xx_sdk_8_32_00_07/docs/driverlib/cc13x2x7_cc26x2x7/driverlib/group__sysctrl__api.html).

## Existing-owner host source proof

`b4_v4_herdsman_overlay.py` applies only after genuine pinned `herdsman_overlay.py` (SHA receipts checked). It adds F1 dictionary, exact `BUFFER160` decoding and read-only guarded `ZStackAdapter` and herdsman Controller methods. The existing **single ZNP mutex** checks port availability, waiter emptiness and live OTA predicate before transmitting; no new serial owner exists. `b4_v4_z2m_overlay.py` applies only after the source-pinned Zigbee2MQTT 2.14.0 OTA guard and exposes a default-OFF manual v4 entry, reusing the same private OTAUpdate state and herdsman Controller. No periodic sampling, separate extension or MQTT request.
