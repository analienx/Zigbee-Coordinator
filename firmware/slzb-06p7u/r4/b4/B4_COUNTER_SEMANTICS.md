# B4 counter semantics / proof boundary

Status (2026-10-17): **one experimental SRSP-enqueued counter is native-linked in both real P7U CCS builds; other counters remain NOT_MEASURED.** `B4_SOURCE_HOOK_MATRIX.json` is a source-to-function research crosswalk, not a claim that any counter increments at runtime.

A metric may transition `NOT_MEASURED -> SOURCE_PATH_IDENTIFIED -> HOSTED_NATIVE_LINKED` only when a real event producer, caller context (ISR/callback/task), increment, type, storage, validity and output serialization are each verified at the pinned source and in the actual linked ELF. Only then may CI qualify width, saturation/wrap, concurrency, stack overhead and performance under loaded SRSP/AREQ traffic. In particular, a function name match is not a counter hook.

* **Units and chronology:** UART bytes != NPI frames != MT requests != AF local SRSP != `AF_DATA_CONFIRM` != ZCL response != RF delivery. `UART2_write` acceptance != `NPITLUART_writeCallBack` completion != host USB receipt. The callback at `npi_tl_uart.c:255` has a `status` argument; classification of successful TX_FINISHED requires linked semantic proof.
* **Absent hook:** validity bit **0**, not a zero-valued counter, and never an all-ones sentinel. Unavailable B2 route/NWK or B3 nonsecret NV error remains UNKNOWN.
* **Unsigned 32-bit:** zero and `0xffffffff` are valid values when validity=1. Wrap-aware subtraction is disallowed by default. It requires source-qualified matching radio epoch, coherent monotonic uptime/sequence, same counter validity, documented width and positive non-ambiguous sample interval. Host-process epoch alone is insufficient.
* **Reset:** radio boot entropy/reset-cause provider is NOT_MEASURED. v3 on-wire capability is not an attestation. No radio epoch identity generation is implemented here.
* **HOLD:** B1 `HOLD_NV/HOLD_SECURITY` read-only status is an optional capability only where NPI is reachable; no key/NV reads, formation, RF or security-gate bypass.
* **Concurrency:** NPI task and UART callback producers have separate scheduling. No `volatile`-only multiword snapshot may be promoted to stable evidence. Use tiny bounded critical sections around read/copy, not MT send/formatting under critical section; no synchronous IO from callbacks.
* **Probe effect:** B4 must not alter SRSP retry, queue priority, radio control, NPI transport scheduling or OTA pacing. Read-only must be tested against unchanged stock ping/version/AF/ZDO control.
* **Saturation and provenance:** explicit per-counter validity plus wrap/saturation policy must come from actual native code. Placeholder data is never serialized into F0 to manufacture coverage.

**Native gate:** verify compiled TI 8.33 source, two genuine CCS 12.8 + ARM Clang 3.2.2 links at identical head, ELF/XML/HEX/BIN hashes, map symbols and SRAM/heap/stack delta, protected NV `0xAA000..0xADFFF`, CCFG geometry and known UART0 DIO12/DIO13 at 115200 without RTS/CTS. Do not treat offline Python or C fixture success as linked firmware evidence.

## Probe-generated counter side effect and late-SRSP ambiguity (direct code-review finding)

The observed `srsp_enqueued` count includes the diagnostic command's own SRSP enqueue if the previous F0 command reaches the queue. It is **not** a count of independent application/ZDO/AF work, and a delta cannot be adjusted by subtracting 1 without transaction/boot identity. `B4_NpiSrspEnqueued` is updated in both pinned TI `NPITask_sendToHost` and `NPITask_processStackMsg` pre-existing critical sections.

F0 v3 requests carry no unique nonce and responses no echo. A late SRSP after a waiter timeout can alias a later request; 30-second cooldown alone cannot guarantee transport drain. The host now disables **only experimental F0** for the remainder of that Znp owner session after an ambiguous failure, while ordinary SYS_PING/AF/ZDO remain enabled. Counter discontinuity or untrusted reboot is not a qualified epoch. A future ABI v4 would need authenticated/uniquely correlated request–response semantics plus source-backed boot generation; no v4 was implemented.

### NPI TX queue gauge expansion, source-only pending native proof

New v3 indices 0 `srsp_depth`, 1 `srsp_high_water`, 2 `async_depth`, 3 `async_high_water` supplement existing index 4 `srsp_enqueued`. In the exact pinned TI `npi_task.c` each of the two TX queues has **two** successful enqueue producers and **one** dequeue consumer, each inside existing `OsalPort_enterCS/leaveCS`. Enqueue increases the matching software depth (saturates at UINT32_MAX), updates its HWM, and a nonempty stock dequeue decrements depth without underflow. The snapshot copies all five counters under a single tiny pre-existing-style CS; serialization and MT send occur after it. No separate `Queue_dequeue` or `Queue_get` is called for diagnostics. The counts measure pending `NPI_QueueRec` transmit records, not TX-FIFO bytes or host-confirmed receipts. Reset/overflow qualification remains UNKNOWN, so long-interval deltas and cross-boot inference remain forbidden. `NPI_SREQRSP` controls validity of synchronous fields and zero serialization on builds without it. This amended source still requires current-head genuine TI ELF plus bounded runtime stack qualification.

### Stock NPI mode and logical SRSP subset within general queue (CR-16)
The pinned P7U projectspec and SDK `znp_cnf.opts` do not define `NPI_SREQRSP`. Stock `NPIFrame_frameMsg` places SOF before LEN/CMD0/CMD1 and labels all outbound frames `NPIMSG_Type_ASYNC`. Consequently the prior source hook inside `NPIMSG_Type_SYNCRSP` was compiled out and could not measure real SRSP traffic. **Current code leaves NPI mode untouched** and identifies SRSP within the general TX queue using `(pBuf[1+MT_RPC_POS_CMD0] & MT_RPC_CMD_TYPE_MASK) == MT_RPC_CMD_SRSP` under existing critical sections and bounded frame-size check. It increments cumulative SRSP enqueue, logical SRSP pending depth/HWM at both general producers and decrements at the single general queue consumer when that SRSP frame dequeues. If a future build genuinely defines `NPI_SREQRSP`, the existing dedicated SRSP producer/consumer paths provide the same logical metrics, and fallback classifier is disabled at compile time. New firmware reports validity `0x1F` in either qualified mode; `async_depth` under stock mode is **TOTAL general NPI TX records (including SRSP)**, not a disjoint AREQ-only count. No TI scheduling/priority/watchdog change, no new Queue operations. UART/host receive, pending-in-driver, RF and causal origin remain unmeasured. Exact compiled native proof is required; the earlier ELF's mask `0x0C` proved the original instrumentation incomplete.
