# NV2 integrity scope and evidence

This source overlay targets TI SDK `3615ad5d3f4f271258d18a2f5ce1785064ff9a58`,
`source/ti/common/nv/nvocmp.c` blob
`01b2b0827d278c10c012b33e5791e53bc5662f10`. `apply_b1.py` checks the original
blob before `patch_nv_integrity.py` changes it. The independent CRC donor is
`source/ti/common/nv/crc.c`, blob
`55f7bc7b617cde41f46110216d897ddfc908b870`.

The pinned defaults are `NVOCMP_NVPAGES=2`, `NVOCMP_HDRLE=0`,
`NVOCMP_FASTOFF=1`, `NVOCMP_FASTITEM=0`, migration disabled. `HDRLE=0` applies
to compressed item headers; the Cortex page/compaction fields use their normal
little endian memory representation. TIRTOS7 alone does not select a POSIX
lock in this donor: the explicit `NVOCMP_POSIX_MUTEX` or `NVOCMP_POSIX_SEM`
define selects it; otherwise the priority gate is compiled.

`b1_nv_probe` reads only the two 8192-byte NV2 pages, with 32-byte scan buffers,
a bound of 4096 backend reads, and a strictly decreasing backward item chain.
It checks version/signature/cycle/allActive, ACT/FULL plus XDST page roles,
formatted compaction header signatures, normal/completed modes, an empty
destination body, each item length/status/signature, and every item CRC.
The CRC covers payload and the first four compressed header bytes plus the
length byte with CRC bits masked, using TI CRC-8 polynomial `0x97`, initial 0.
Inactive obsolete rows remain valid positive controls. No item bytes are
returned in diagnostics.

Unknown formats, incomplete item writes, gaps, invalid lengths, failed reads,
pending compaction, and ambiguous page pairs stop before donor initialization.
An internally consistent candidate still needs the separate NIB/security gates.
During existing-state initialization, a donor attempt to mark a duplicate
inactive, repair, write, or erase fails closed before NVS mutation. After
preflight, the real NV2 page scan rechecks coherent live page headers, and
initialization exits immediately on failed page/item reads. This fixes the
donor's page version OR signature acceptance and silent recovery entry.

The real read/write/erase functions check page bounds and fatal/security HOLD.
Backend errors, CRC faults, and voltage denial latch HOLD. A later successful
read, cleared per-transaction `failW`, or restored voltage does not resume
mutation. A true blank synthetic fixture can still use the donor's normal
formatting path when the test explicitly defines `B1_FACTORY_BOOT_AUTHORIZED`.
Production builds do not gain that authorization.

`make_nv_backend_harness.py` extracts and compiles the actual NV2 initializer,
page scan, offset search, item search/header/read/write, CRC, and NVS backend
bodies. Synthetic NVS, RTOS allocation, and a compaction sentinel are explicit
boundaries. Fixtures are generated by actual `NVOCMP_writeItem`, exercising
both small and large writes, then rebooted through actual admission and donor
initialization. The accepted resume and hostile tests assert zero compaction
calls, writes and erases. The factory positive asserts two synthetic erases
and ten writes; healthy runtime write/erase controls confirm the gates permit
valid operations. Fast-item and the actual default slow-item variants compile
separately. `make_nvocmp_init_harness.py --rtos priority|sem|posix` additionally
checks the actual init API's lock/open/geometry failure branches using a stub
for the downstream initializer.

These are HOSTED_SYNTHETIC tests when run on GitHub; local execution is only
development feedback. They do not prove physical brownout behavior, runtime
compaction at every interrupted operation, RF silence, wear, or compatibility
with an installed vendor image. A valid-looking NV2 slice cannot prove that
another historical image did not use additional NV pages outside the allowed
region. Such layout provenance stays unknown; no reads outside NV2, migration,
or device operations are authorized by this work. N24 and stock-NV admission
therefore remain partial/open even when the listed source tests pass.
