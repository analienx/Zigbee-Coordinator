The flash operation for V53 is consumed. It must never be replayed. Nothing else in this document authorizes any hardware action.

## Root cause (measured, V52 live capture)

- The NWK task spent about 98 % of its CPU in NV reads. Each received frame triggered one linear NVOCMP scan, about 10 ms each.
- It was not MAC retries (every data request succeeded) and not OSAL timers. The V52 timer change was a candidate and did not address this.
- V53 adds an 8 × 32-byte exact-match NV read cache with a generation race guard. The cache is cleared on every NV write, delete, compact, doNext and erase. Evidence page B1E7 reports only counters and item IDs, never NV bytes.

## Operational notes

- The first open after the hang-evidence capture hit a ping timeout, because the radio was still streaming a backlog. A plain app start fixed it. The driver's hang phase should stop the host, capture, and restart it with a bounded retry.
- The old custom P7U helper apps are uninstalled: Recovery Guard, lifecycle manager and preservation probe. Their registry containers are removed. The host sampler was dropped, so PR #197 is unused.
- The custom host had left device-side bindings to a byte-reversed form of the coordinator IEEE address on 21 devices (72 entries). They were removed on each device, with the device confirming each removal. No database entries were edited by hand. The affected devices were reconfigured afterwards.

## Open items

1. **Adapt the tooling for the official app.** `hang-evidence` and the flash driver still assume the custom P7U host owns the UART. They need changing before any future hardware action. The one-UART-owner rule still applies. The source review confirmed that the capture fails closed (it never opens the TTY) but therefore cannot read the hang record ([review F1](REVIEW_V53_2026-10-31.md#f1--high-hang-evidence-and-the-flash-driver-only-work-with-the-retired-custom-host)).
2. **Long-run stability.** The measurements above cover roughly four hours after the switch. Stability over days under the official app is not demonstrated yet.
3. **Qualification gates.** The gates in `README.md` (independent review, physical qualification, rollback proof) are not closed. Deployment happened under the one-shot procedure, but this repository does not yet say V53 is qualified. That call belongs to the owner.
4. **PR state — done.** `main` now holds the V53 firmware and delivery as one latest-version commit; the version-by-version history and files used only by earlier versions are not carried. The installed commits, firmware `8ec1439` (PR #195) and delivery `ed42122` (PR #196), stay retrievable through their PR refs. All earlier-version P7U branches are listed for deletion in the [1 Nov branch audit](../../docs/BRANCH_PRUNE_AUDIT_2026-10-31.md).
5. **Rollback.** Going back to the custom host requires restoring the coordinator database and approval state from the saved backup, which is documented in the private handover. Do not roll back as a fix for a hang.
6. **Review follow-ups (1 Nov).** The [all-phases review](REVIEW_V53_2026-10-31.md) re-composed the deployed source locally and found no defect in the root-cause fix or its supporting layers.
   - **Fixed in source as a V54 candidate**, not built natively or flashed: the NV read cache now honours B1's NV HOLD, never stores the TCLK seed, and ignores NULL or zero-length reads (F3, F6, F7).
   - **Fixed in tooling:** the flash driver's `hang` phase now refuses unless the paired host is installed (F1, partial). A local composition script now produces the deployed C (F5, partial).
   - **Open:** measure live NV4 `active_records` before the network grows, because boot admission refuses at 1,024 distinct NV items, below the R4 profile's own capacity (F11). Also open: official-app hang tooling (F1), and the F2/F4 decisions after a soak.
